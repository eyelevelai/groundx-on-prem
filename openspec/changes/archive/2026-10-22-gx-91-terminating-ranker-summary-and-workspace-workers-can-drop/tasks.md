- Task 5.1 is split by what each run can prove. The live spec requirement "Shutdown behavior is proven on the real images before release" was amended to match. The local run passed on 2026-10-22 (evidence in EyeLevel-ai/engineering-context#207, `evidence/lifecycle/`); the EKS run is still to do.
- Duplicate default-only render cases were removed from `celery_test.yaml` and `inference_test.yaml` (the default ranker, summary and workspace grace period and `exec`, the default 870 s stop wait and one-worker groups, and the default 14-worker ranker group), because the hand-patched snapshots already pin those renders; the "Covered by" names in tasks 1.2, 2.1 and 2.2 that point at those cases now mean the snapshots. The override, floor, worker-resize, schema-rejection and flipped workspace startup cases remain.
- Task 5.1's EKS run passed on 2026-10-22 on validation-infra (`groundx-validation`, us-east-2) with the real ranker (14 workers), summary and workspace images: every case passed (shape, ranker drain under 40 search clients, reserved messages returned to the queue, summary drain with a summary running across SIGTERM, idle workspace, end-to-end). Evidence: EyeLevel-ai/engineering-context#207, `evidence/eks/`; the table is in eyelevelai/groundx-on-prem#150.
- On the real summary image (vLLM 0.28.0) the Celery worker stops taking tasks at SIGTERM and finishes its running task, but never exits after its warm shutdown: the vLLM engine process it spawned keeps it alive, so Supervisor kills it at the stop wait on every pod stop. With this change's 900-second default that is 870 seconds; observed on EKS: SIGTERM at 12:05:27 UTC, worker killed by SIGKILL at 12:19:58, pod gone after 14 min 44 s. The pod still exits inside its grace period and no task is lost, so the 900-second default stands. Making the worker exit on its own, and whether to lower the summary default to 300 seconds meanwhile (also tested on EKS: worker killed at 271.5 s, pod gone at 291 s, a running summary still finished), are tracked in GX-126. The live spec's summary scenario notes the kill at the stop wait.
