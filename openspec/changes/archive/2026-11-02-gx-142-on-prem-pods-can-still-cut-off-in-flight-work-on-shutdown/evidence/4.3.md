### Control: base config with a long docker grace

This run separates gunicorn's own cut-off from the container kill. In the base runs above the 30 s `docker stop` SIGKILL (exit 137) and gunicorn's default `graceful_timeout` of 30 s fire at the same moment. So all five base images were run again with `docker stop -t 150`:

| API | Expected | Actual | Pass/Fail |
|---|---|---|---|
| extract / layout / ranker / summary / workspace, base config, `-t 150` | gunicorn itself drops the request at ~30 s although the container may stay up to 150 s | All five: curl (52) empty reply 30.1 s after SIGTERM, then `Shutting down: Master` and **exit 0**, so the container was not SIGKILLed. 35.14 / 35.14 / 35.14 / 35.13 / 35.12 s from the request | Pass |

This shows the 30 s cut-off is in the previous gunicorn config: no `graceful_timeout`, so gunicorn's default of 30 s applies. It is not only the pod's default 30 s grace.

## Stand-in

- Each image is `gx142-standin-api-<api>-<new|base>:local`, built `FROM` the API's real image. The USER (1001) is kept and no USER line was added.
- Each image adds `/app/standin.py` and the rendered conf at `/app/gunicorn_conf.py`. Both are COPYed from a build context, with no bind mount.
- `standin.py` is a raw ASGI app with lifespan startup and shutdown. `GET /slow` does `await asyncio.sleep(60)` and returns `slow-ok`; every other path returns `ok`.
- Only `wsgi_app` was changed in each conf, for example:

```
< wsgi_app = "server:app"            (extract, workspace; layout: document_api_server:app; ranker: ranker_server:app; summary: summary_server:app)
> wsgi_app = "standin:app"
```

`ps` inside the container shows PID 1 is the gunicorn master. bash exec-optimises the `-c` list, so `docker stop`'s SIGTERM reaches gunicorn directly:

```
1 /usr/local/bin/python /home/python/.local/bin/gunicorn -c /app/gunicorn_conf.py --capture-output --enable-stdio-inheritance
7 ... gunicorn ... (worker)
8 ... gunicorn ... (worker)
```

Versions seen: gunicorn 26.2.0 and uvicorn 0.54.0 on extract and python-api; gunicorn 23.0.0 and uvicorn 0.54.0 on workspace-runner.

## Procedure (`case.sh <api> <new|base> <port> <grace>`; all 10 run in parallel on host ports 18101-18110, the control on 18121-18125)

1. `docker run -d -p 127.0.0.1:<port>:8080 <img> /bin/bash -c '<rendered start command>'`, then wait for `GET /` to return 200.
2. Send `curl -sS -m 400 http://127.0.0.1:<port>/slow` in the background.
3. 5 s later, run `docker stop -t <grace>`. The grace is the chart's rendered `terminationGracePeriodSeconds`, or 30 for the base chart, where it is not rendered.
4. Record curl's result and time, `docker inspect` (exit code and timestamps) and `docker logs -t`.
