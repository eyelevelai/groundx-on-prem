# Tasks: GX-161 one shared shutdown rule for every Go service (chart half)

Checks run from the repo root via `bash -c`. Set `GX_ON_PREM_HELM` to a Helm v3.19.0 binary with the pinned helm-unittest plugin, or leave it unset when `helm` on `PATH` is v3.19.0; every Helm check stops with an error on any other version. Suite checks run on a `mktemp -d` copy of the chart, so the worktree's snapshots are never rewritten, and the suites that render the Google OCR credentials get the gate's throwaway fixture written in the format `.build/bin/validate-helm.sh` uses. No check uses `helm unittest -u`, and no check prints a rendered manifest. "Base" is `git merge-base HEAD origin/0.3.0`, not the moving `origin/0.3.0` tip. Task 4.2 runs the full suite, which took 283 s on the authoring machine on 2026-11-05; keep `ACCEPTANCE_CHECK_TIMEOUT` at its 600 s default or higher.

Mirror rule: every template, `values.yaml` and `values.schema.json` edit under `src/groundx/` is copied byte-for-byte into `helm/` in the mirror task of the same group. `helm/` has no `tests/` tree. The existing snapshots go stale from task 1.1 on and are hand-patched once, in task 4.2.

This repo is PRIVILEGED: only template, schema, test and doc edits; never execute `bin/` scripts, and the pre-push gate (`.build/bin/validate-helm.sh`) is run by the push step, not by a task check.

See workspace `openspec/changes/gx-161-on-prem-go-services-handle-shutdown/tasks.md` for cross-service coordination and deferred items (cashbot-go signal handling and `drainSeconds` on `config.Server`).

## Rollout sequence (no secret changes, no SQL, no manual ops)

1. Merge and release the chart on the `0.3.0` line; every Go Deployment restarts once because `config-hash` changes.
2. Roll cashbot-go images separately; the chart is safe in any order for the four request-serving services, and `largeFileDeliver` and `postProcess` begin draining as soon as the chart lands (see `docs/upgrades.md` after task 4.3).
3. Chart and app version bumps are left to the release step.
