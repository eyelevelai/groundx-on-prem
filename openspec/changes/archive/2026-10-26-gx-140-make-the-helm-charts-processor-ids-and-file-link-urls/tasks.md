# Tasks: GX-140 configurable processor IDs and file link URLs

Checks run from the repo root via `bash -c`. Set `GX_ON_PREM_HELM` to a Helm v3.19.0 binary (with the pinned helm-unittest plugin); every Helm check stops with an error if it is unset or another version. Task 4.1 also needs a real `python3` first on `PATH`, because `validate-helm.sh` calls bare `python`. Suite checks run on a `mktemp -d` copy of `src/groundx` with the gate's throwaway Google-OCR fixture written in the same format as `.build/bin/validate-helm.sh`, so the worktree's snapshots are never rewritten. No check uses `helm unittest -u`, and no check prints a rendered manifest: the checks print only the unit-test summary, failing test names, and gate step markers.

Mirror rule: every template, `values.yaml` and `values.schema.json` edit under `src/groundx/` is copied byte-for-byte into `helm/` in the same task.

## Rollout sequence (no secret changes, no SQL)

1. Release the chart with the next `0.2.8` cut. An upgrade with unchanged values renders the same `config.yaml`, so the Go services' `config-hash` annotation does not change and nothing restarts because of this change.
2. Merge the held `groundx-studio-harness` documentation PR only after that chart release is published.
3. Setting the keys for GroundX Cloud is separate deployment work.
